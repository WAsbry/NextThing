# 登录登出及头像修复

## 问题背景

三个相关 Bug：
1. 退出登录按钮点了没反应，用户还停留在个人信息页
2. 登录/注册失败时（如用户名已存在），Toast 只显示"网络错误：HTTP 400"，不显示服务器返回的具体原因
3. 设置页"我的"显示默认头像，但进入用户信息页后头像变成了 emoji 占位符

## 问题根源

### 退出登录无效

`UserInfoViewModel.logout()` 只调用了 `userUseCases.logout()`（清除本地用户数据），没有清除 JWT Token，也没有通知 UI 跳转到登录页。

```kotlin
// 修改前：只清了本地用户
fun logout() {
    viewModelScope.launch {
        userUseCases.logout()
    }
}
```

完整登出需要三步：清 Token → 清本地用户 → 跳转登录页（清导航栈）。

### 登录错误信息丢失

服务端业务错误（如用户名已存在、密码错误）通过 HTTP 400 返回，响应体是 JSON：
```json
{"code":1001,"message":"用户名已存在","data":null}
```

但 `LoginViewModel` 的 catch 只有通用 `Exception`，`HttpException`（Retrofit 抛出）被当成网络错误处理。

### 头像不一致

设置页用 `AsyncImage` + `R.drawable.preset_avatar` 作为 fallback，而用户信息页用 `"👤"` emoji 文字作为占位。两处渲染逻辑不统一。

## 修改思路

| 文件 | 改动 |
|------|------|
| `UserInfoViewModel.kt` | 注入 TokenManager，logout 时先 `tokenManager.clear()` 再清本地用户；新增 `logoutEvent: StateFlow<Boolean>` 通知 UI |
| `UserInfoScreen.kt` | 新增 `onLogout` 回调参数；`LaunchedEffect` 监听 logoutEvent 触发回调；头像统一用 `AsyncImage` + preset_avatar |
| `NextThingNavigation.kt` | UserInfoScreen 的 onLogout 用 `popUpTo(0) { inclusive = true }` 清空导航栈 |
| `LoginViewModel.kt` | 新增 `HttpException` catch 分支 + `parseServerError()` 从 HTTP 400 body 提取 message 字段；登录/注册成功后同步服务器头像到本地 |

### 核心代码：Retrofit 错误解析

```kotlin
private fun parseServerError(e: HttpException): String? {
    val body = e.response()?.errorBody()?.string() ?: return null
    val type = object : TypeToken<Map<String, Any>>() {}.type
    val map: Map<String, Any> = gson.fromJson(body, type)
    return map["message"] as? String
}
```

## 经验总结

1. **JWT 登出流程三件套**：清除 Token（DataStore）→ 清除本地用户数据（Room）→ 清除导航栈（`popUpTo(0) { inclusive = true }`）。少做任何一步都会出问题——不清 Token 会自动重新登录，不清导航栈用户可以返回已登录页面。

2. **Retrofit 错误处理分层**：`HttpException`（有状态码和响应体，是业务错误）和通用 `Exception`（网络/序列化错误）要分开处理。前者解析 body 取 `message` 给用户看，后者展示"网络异常"。

3. **UI 一致性**：同一个数据（用户头像）在不同页面展示时，渲染逻辑必须统一。最佳实践是抽成共享 Composable 组件，而不是每个页面各自实现。

4. **面试话术角度**：可以讲 JWT Token 管理的完整生命周期——登录获取 → AuthInterceptor 自动注入 → 刷新机制 → 登出清除，这是一个完整的认证流程设计。

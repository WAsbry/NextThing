# 定位系统修复

## 问题背景

首页无法获取位置信息，连WiFi也拿不到，天气数据也因此无法加载。用户点击"获取位置"一直转圈超时。

## 问题根源

经过日志分析和代码审查，发现三个叠加问题：

### 1. 权限检查逻辑过于严格

`AmapLocationServiceImpl.hasLocationPermission()` 和 `LocationServiceImpl.hasLocationPermission()` 都要求 `ACCESS_FINE_LOCATION && ACCESS_COARSE_LOCATION` 同时授予。

Android 12+ 引入了精确位置和粗略位置的分级授权，用户可能只授予粗略位置权限。WiFi+基站定位只需要 `ACCESS_COARSE_LOCATION`，不需要精确位置。

```kotlin
// 修改前：必须两个权限都有
fineLocationGranted && coarseLocationGranted

// 修改后：有任意一个即可
coarseLocationGranted || fineLocationGranted
```

### 2. 高德 API Key 认证失败（主要原因）

Logcat 报错：`错误码: 7, auth fail:INVALID_USER_SCODE`

SHA1 签名匹配，但高德控制台上注册的包名是 `com.example.nextthingb1`（初始模板包名），而实际应用包名是 `com.nextthing.app`。

修复：到高德开放平台控制台 → 编辑 Key → 包名改为 `com.nextthing.app`。

### 3. Google FusedLocationProvider 回退超时不足

AMap 失败后回退到 Google 服务，但只给了 5 秒超时。而 `LocationServiceImpl` 内部是多级串联（粗略网络8s → 高精度15s → GPS 20s = 最多43秒），5 秒连第一步都跑不完。

```kotlin
// 修改前
private const val FALLBACK_TIMEOUT = 5000L

// 修改后：给内部串联足够时间
private const val FALLBACK_TIMEOUT = 20000L
```

同时简化了 `LocationServiceImpl` 的定位策略，砍掉独立的 GPS 步骤（室内无用），改为：粗略网络(12s) → 高精度(15s) → lastKnownLocation。

### 附加问题：国内设备 Google Play Services 不可用

红米 K60 Ultra 国行系统的 FusedLocationProvider 无法返回位置结果。这是国内 Android 设备的普遍情况，定位方案应以高德等国内 SDK 为主。

## 修改思路

| 文件 | 改动 |
|------|------|
| `AmapLocationServiceImpl.kt` | 权限检查改为 OR；回退超时 5s → 20s |
| `LocationServiceImpl.kt` | 权限检查改为 OR；简化定位策略，砍掉 GPS 独立步骤 |
| 高德控制台 | 包名更正为 `com.nextthing.app` |

修改原则：**国内设备以高德为主，Google 为辅；权限检查宽松（OR），定位策略精简（去 GPS）**。

## 经验总结

1. **Android 12+ 权限分级**：粗略位置（COARSE）和精确位置（FINE）是独立授权的，应用应该用 OR 逻辑检查，不要假设两个都有。粗略位置足以支持 WiFi+基站定位。

2. **高德定位错误码速查**：错误码 7 = KEY 认证失败，排查三要素：SHA1 签名 + 包名 + API Key 值是否在控制台上完全匹配。

3. **国内设备定位方案选型**：Google FusedLocationProvider 在国内大部分设备上不可靠（国行 ROM 缺少完整 GMS），定位方案应以高德/百度等国内 SDK 为主力，Google 服务只能作为海外版本的备选。

4. **超时级联累加问题**：定位系统往往是多层嵌套（SDK层 → 服务层 → ViewModel层），设计超时要考虑级联总和：AMap(8s) + Fallback(20s) + ViewModel(35s)，每一层的超时要给下一层足够的空间，避免外层超时打断内层的正常流程。

5. **面试话术角度**：这是一个典型的"多层 fallback 定位系统"设计，可以讲：主路径用高德（国内体验好），降级用 Google FusedLocation（海外兼容），兜底用 lastKnownLocation（缓存），每一层有独立的超时和错误处理。

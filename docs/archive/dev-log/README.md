# NextThing 开发问题战斗日志

这个目录用于记录开发过程中遇到的高价值问题。它不是复习资料，也不是完整日报，而是后续整理面试项目经验的原始证据库。

## 记录原则

- 只记录有面试价值的问题：定位链路、技术取舍、架构调整、性能优化、用户体验改造。
- 每条控制在 5 到 8 行，先保留事实，不急着写成话术。
- 必须包含证据：日志、错误信息、代码位置、验证方式至少有一个。
- 后续整理项目经验时，再从这里提炼 What / Why / Deep。
